# Two connections, feature list and picture audit — October 1, 2026

The welcome screen now tells users that both connections are required: **1. Connect to your TV or home device**, then **2. Connect to your phone**. The same two stages appear in the iPhone and Android beginner guide and Devices page. The current guide section is highlighted without a completion tick or a claim that a connection exists.

The old welcome example about a quiet film and a loud advert is removed. Its card position now contains the shared 21-entry feature catalog, with **Skip series intros**, **Lower volume during commercials** and **Universal remote controls** first. The catalog includes sound presets, equalizer, accessibility audio/captions, languages, voice, profiles, restore/undo, history, recovery, phone handoff, background protection, privacy, feedback, explainable suggestions, accessories, illustrated/photo setup and voice-input display. Device controls are labeled planned and conditional on supported devices. The two explorable input/setup entries are distinguished from planned controls. Completing instructions does not authorize or verify physical control.

## Audit scope and findings

All 39 routes and their 345 numbered pictures were reviewed for instruction order, TV/phone surface, highlighted item, action, qualification notes and completion wording. The offline HTML guide and native catalogs are generated from `contracts/setup_guides_v1.json`; they must stay identical. These are schematic directions, not screenshots guaranteed to match every firmware version.

| Finding | Correction | Evidence boundary |
|---|---|---|
| LG PIN entry asked users to type while highlighting Next. | Highlight the PIN field and add a separate picture for tapping Next. | The official ThinQ flow distinguishes PIN entry and confirmation. No real PIN is stored. |
| LG and VIZIO assistant pictures favored one assistant although the text allowed a choice. | Show a generic chosen-assistant guide/app. | Account authorization occurs in the official app. Provider availability remains regional. |
| Google faster phone setup omitted phone-version prerequisites and ended by assuming a Google Home download. | State iOS 17+ or Android 9+, the documented iPhone Google TV app-version condition, and finish on the TV home screen. | Use this route only if the TV actually offers the newer camera-based setup. |
| Sony's legacy route placed Remote Start after account selection. | Put the optional Remote Start choice before account selection, matching the legacy instructions. | Yes is an illustrated example, not required consent; standby energy use is disclosed. |
| Optional linking and standby choices could look mandatory. | Explicitly identify Link/Skip and Yes/No as user choices. | Follow the user's actual choice and the screen on the actual device. |
| Samsung's alternate model-information label was incomplete. | Include Contact Samsung as an alternative to About This TV. | Menu generation, region and model remain relevant. |
| Five old official source URLs failed. | Replace LG model information, Roku Alexa and three TCL manual URLs with accessible official sources. | A working link is not independent proof of compatibility. |

## Deterministic verification and next check

Red/green regressions cover LG PIN focus/confirmation, neutral assistant illustrations, Sony legacy order and Google faster-route prerequisites. Catalog tests validate source references, surfaces, focus bounds, ordering and generated parity. Tutorial tests validate exactly two ordered connection stages, all catalog entries, rejected actuation metadata and preview/planned labels. Native walkthroughs must show the replacement card, reach its first and last entries, keep navigation usable and reach the separately titled phone connection step.

The local repository suite passed **1,824 tests and 14 subtests**. Generated tutorial/setup/offline catalog checks, shell syntax and diff whitespace checks passed. Native build, screenshot and artifact results are recorded with the delivered commit in draft PR #32.

The smallest remaining picture-fidelity check is to compare the schematic directions with the exact physical model, firmware, country and official-app version before claiming verified hardware compatibility. A matching picture, guide completion, app permission or assistant account link never establishes an AQSS capability lease, physical execution or observed physical truth. No latency, power, supported-device breadth or production-readiness measurement is inferred from these UI changes.
