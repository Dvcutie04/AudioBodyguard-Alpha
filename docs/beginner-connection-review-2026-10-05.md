# Beginner connection-flow review — October 5, 2026

The owner asked for a clearer start-to-finish connection process, minimal text, understandable pictures, optional explanations and less repeated work. This revision applies the already-researched progressive disclosure and bounded local continuation in `simple-onboarding-research-2026-10-01.md`, `sequential-guidance-research-2026-09-29.md` and `voice-photo-research-2026-09-29.md`. It introduces no new compatibility, discovery, account-linking or physical-control claim.

## Review 1: one current task

The phone stage now has one prominent picture action. TV and selected Google Home/Alexa instructions remain available in its Need help panel, rather than competing with the phone task. The TV stage emphasizes its TV picture action; selected assistant paths remain separate. The tutorial's optional Next action has secondary styling on these two screens, so it does not compete with the picture action. Exit Home and exact Back to Tutorial remain available.

Every setup introduction and numbered picture uses Need help / Hide help. The iPhone uses a question-mark symbol. TV-system selection now offers identification pictures when the user is unsure. Model/applicability information remains visible before starting, and required passwords, permissions and approvals remain in the numbered directions. Each picture's help also exposes manufacturer references without requiring a browser detour to complete setup.

## Review 2: bounded automation and Back

An explicitly selected system with one primary documented guide opens that guide's preparation page directly, removing the redundant route picker. The user still presses Start guide or Resume guide. Ambiguous TV systems and multiple primary routes still require a choice. Alternative routes remain under Need help > Other setup options. Back visits actual previously displayed pages, including returning directly to the caller when no picker was shown.

The tutorial reuses a previously chosen, valid TV system when reopening that same brand's instructions. Changing brands invalidates incompatible remembered choices. This is reuse of a user's local selection, never device discovery or verified identity. Existing Roku TV-to-phone continuation and per-route learning bookmarks remain intact.

The iPhone phone guide offers iPhone pictures. The Android phone chooser offers Pixel and Galaxy pictures, never iPhone menus. Existing Android manufacturer-based routing is retained; unknown manufacturers still require a choice. On recreation, the selected TV context is restored before validating its assistant route, and a manually opened alternative picker is not automatically replaced.

## Review 3: instructions, pictures and truth

The shared catalogue is unchanged: 45 routes and 389 numbered illustrations, including separate phone, TV, Google Home and Alexa paths. Every instructional step retains its surface, visible menu labels, numbered focus target, action and source references. The longest essential direction is 30 words. The existing Roku and Philips menu layouts remain system-specific; no new generated screenshot or another manufacturer's photograph is substituted.

Images are labelled instructional diagrams, not verified photographs of every model, country or firmware. The original white-background rose and transparent color/grayscale humanoid head are unchanged. The connected Appetize build is an explicitly marked visual demo.

Local navigation, a selected brand, a completed picture sequence, OCR and an IP hint cannot verify a physical connection or grant authority. Current coverage, capabilities and physical output remain Unknown and no command is dispatched. Real vendor pairing automation requires the separate research and authenticated integration described in the existing AQSS charter; it is not implemented by this usability revision.

## Validation

Shared-catalogue generators, staging checks and native walkthrough expectations cover the single-guide shortcut, optional alternatives, immediate previous-page Back, TV identification help, remembered TV system, simple phone defaults, recovery to earlier instructions, correct phone-family images, Roku continuation, cancellation, rotation and large text. Exact simulator/emulator run results and delivered artifact provenance are recorded in draft PR #32. Automated walkthroughs are implementation evidence; ease of use by an unassisted junior-high student still requires a user trial.
