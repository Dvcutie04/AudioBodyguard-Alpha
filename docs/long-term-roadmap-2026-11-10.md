# Audio Bodyguard / AQSS-36-OMEGA — evidence-gated long-term roadmap

**Draft checkpoint:** November 9, 2026, 22:30 Pacific. **Status:** proposed implementation sequence for review, not release authorization or a physical qualification certificate. This supplements, rather than rewrites, the dated history in [development-roadmap.md](development-roadmap.md). iPhone/iOS and Android are equal product targets.

> **INFERENCE IS NOT REALITY. AI proposes. Policy authorizes. Physical Commit verifies.**

## Decision in one paragraph

The next work is to **finish evidence-based setup reliability and a testable, private owned-device qualification plan**. Do not infer a working TV connection from a successful picture guide, a TCP answer, a certificate fingerprint, a UI showing “Connected,” a cryptographic receipt, or a synthetic acoustic result. Identity, explicit consent, authenticated pairing, a qualified owned audio/output route, independent measurements, continuity of old work, and native iOS/Android behavior are *separate* gates. Prioritize a small independently observable end-to-end route over attempting universal TV control. No hardware purchase, hub or new service is assumed. Release dates and resource/latency estimates require measurements.

### Evidence vocabulary used throughout

- **Verified software (specific source):** named source tree with relevant passing automated/hosted fixture or native UI checks; does not qualify hardware.
- **Implemented, not fully verified:** code or UI exists but missing exact-source, runtime, scenario or screenshot checks.
- **Unrun / unresolved:** an observable acceptance criterion has not been checked, or the root cause is not established.
- **Blocked on hardware / owner authorization:** named real route, consent, independent observation and qualified execution boundary are required.
- **Proposed:** design or feature aspiration with no implementation or qualification claim.

## Cross-cutting research and overlooked work — bounded triage

1. **Accessibility, translation and manufacturer drift — P1.** Record stable, localizable route strings and accessible descriptions; verify keyboard/VoiceOver/TalkBack, dynamic type, high-contrast cyan states and non-English truncation in bounded software samples. Revisit manufacturer and OS references by version/date; avoid copying OEM images as if they were current. A school-age comprehension trial is a *later observed usability test*, not a source assertion.
2. **Privacy and permission lifecycle — P1.** Minimize sensitive addresses, transcripts, audio and photos in report defaults; distinguish process-only recap from protected audit records. Test retention/deletion/recipient-preview behavior with denied/revoked permissions, interrupted Share and restart. Specify actual storage and encryption mechanism before claiming secure local storage.
3. **Supply chain, provenance and determinism — P1.** Inventory GitHub workflow permissions, action/Gradle/Swift/Python dependency pins, reproducible build inputs, code-signing/unsigned distinctions, short artifact retention, external downloads and diagnostic logs. Record exact SHA/tree and runnable test inventory; investigate differences before assigning results to combined-source merges.
4. **Recovery and performance — P1 after a selected route.** Model sticky cleanup owner through failures and callback generations, including OS process death; plan instrumented baseline for latency, dropped frames, battery, wakeups, storage and sustained accessibility behavior. Do not invent benchmark targets or fill hardware fields from a CI fixture.

**Research rule:** new platform or model-specific facts must cite current official publisher, publication/retrieval date, OS/firmware applicability, and unresolved uncertainties. A recommendation is not a green implementation. Treat repository notes as historical inputs; verify externally before changing platform-specific directions.
