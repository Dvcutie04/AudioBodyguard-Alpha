# AQSS-36-OMEGA / Audio Bodyguard — research update

Evidence reviewed September 30, 2026 (America/Los_Angeles). Scope: current development branch, both native shells, deterministic runtime, reference/research modules, tests, workflows and dependencies. This is a targeted research update, not certification of hardware or every platform variant.

The charter remains: inference proposes; deterministic policy authorizes; Physical Commit verifies. Evaluate latency first (eligible event-to-response target below 200 ms), then power, bounded memory/storage and ecosystem compliance, without trading away privacy, security, authorization, independent observation or explicit uncertainty.

## Notion AI Meeting Notes

The user confirmed Notion, rather than a separate product named “Notation.” [Notion's documentation](https://www.notion.com/help/ai-meeting-notes) describes desktop microphone plus system-audio capture, microphone-only browser/mobile capture, external transcription processors, and summaries grounded in transcript plus user notes. Desktop one-to-one capture helps speaker labeling; shared microphones and group/mobile use have limits. Mobile cannot capture the phone's internal call audio. Live processing has temporary local audio and retry retention; offline operation is unsupported.

The public documentation does **not** establish a particular ASR model/version, decoding pipeline, training corpus or independent word-error benchmark. Listing AssemblyAI and other processors does not prove which model handles each session. Cleaner separate audio sources plausibly help accuracy; that is an engineering inference, not a verified explanation of all reported accuracy.

AQSS lessons: separate provisional words from final text, preserve timestamps/source lineage, expose recognition gaps, obtain explicit session consent, bound retention and evaluate false commands. Keep summaries/transcripts proposal-only. Do not copy desktop system-audio assumptions onto phones or silently introduce a cloud fallback.

[Notion's March 18, 2026 release](https://www.notion.com/releases/2026-03-18) adds custom summary context/instructions. That concerns summary quality; it is not evidence that the acoustic transcript is correct. [AssemblyAI's public implementation example](https://www.assemblyai.com/docs/getting-started/end-to-end-examples/meeting-notetaker) separates transcription/speaker segments from LLM-generated notes; it is an architectural example, not disclosure of Notion's private implementation.

## Synthesis and next research increments

1. Isolate a platform-eligibility contract for API 37 audio/network behavior; red-green pre-dispatch denial with zero adapter calls; keep the production factory closed.
2. Build a speech evaluation harness around source-timed provisional/final hypotheses, adversarial audio and measured false command rate. Recognition and independent output sensing remain separate.
3. Profile an installed iPhone and Android handset: warm/cold response distribution, background transitions, energy/thermal state and model storage. Hosted simulator results do not qualify the latency target.
4. Map EAT/Matter identities and SCITT audit commitments onto existing canonical finality/fence lineage; do not replace local deterministic acceptance with a cloud log.

No real pairing, protected audio, background coverage or store certification is claimed. Research synthesis above identifies candidates; it does not automatically authorize implementation of an actuation path.
